# 介绍

> 轻量化的工业物联网平台，将设备鉴权、数据存储、协议解析、设备抽象、项目场景管理、应用对接、数据分析与监控告警等基础能力开箱集成，让企业专注业务本身。

## 平台简介

alinkiot 是一款**面向工业场景的轻量化物联网平台**。它把物联网应用所需的通用底层能力——设备接入与鉴权、数据存储、协议解析、设备抽象（物模型）等——沉淀为标准化的基础设施，开箱即用，无需从零搭建。

在此之上，平台进一步提供项目 / 场景的设备组织、数据分析和监控告警等完整的管理能力，并提供开放的对接能力，方便与第三方业务系统或 AI 对接；对于行业内的标准协议（如 Modbus、MQTT）天然支持，对于私有协议则提供插件式的定制能力。企业无需关注底层通信与数据链路的实现细节，即可快速构建自己的工业物联网应用。

**轻量，并不简单**——架构精简、部署轻便，但设备全生命周期管理、安全接入、弹性扩容与无感发布等企业级能力一应俱全。

## 行业背景

物联网在快速发展的同时，也面临以下核心挑战：

| 挑战 | 说明 |
|------|------|
| **协议众多** | 设备通信协议五花八门，标准协议与私有协议并存，难以统一接入与管理 |
| **设备种类繁杂** | 传感器、控制器、网关、定位终端等品类众多，形态与能力差异大，难以统一抽象与管理 |
| **行业形态差异大** | 小到轻量化的自动化监测项目，大到大型物联网平台，不同场景对平台的规模与投入诉求跨度极大 |
| **接入能力建设两难** | 稳定的设备接入是一切业务的基础，却也是企业的隐性负担：自研需要在鉴权、协议、连接稳定性上长期投入，成本高、门槛高；若不自研，又难以把控系统的稳定性与可用性 |
| **投入产出不成正比** | 做物联网只是为了支撑业务，但光是把设备接进来、让它稳定跑，就要投入大量人力和时间，划不来 |
| **缺乏专业团队** | 维护一个设备管理平台需要专业的人，多数企业既招不来、也养不起，更难以管理好这样一支团队 |

alinkiot 针对上述挑战进行了系统性的架构设计，提供一体化解决方案。

## 产品架构

针对不同行业设备种类繁多、协议不统一的现实，平台采用**分层架构设计**，自下而上分为连接层、逻辑层与插件层：连接层专注设备接入、逻辑层专注设备与消息的核心处理、插件层承载可扩展的业务能力，各层职责清晰、独立扩展。

```
┌─────────────────────────────────────────────────────────┐
│  插件层  消息处理 · 流转(Kafka/MQTT/API) · 存储 · 告警 · 分析  │
├─────────────────────────────────────────────────────────┤
│  逻辑层  设备鉴权 · 上下行消息路由 · 会话信息存储              │
├─────────────────────────────────────────────────────────┤
│  连接层  TCP / MQTT 等协议接入                               │
└─────────────────────────────────────────────────────────┘
```

- **连接层**：最底层，负责 TCP / MQTT 等协议的接入，与业务逻辑剥离，专注维持设备的稳定连接
- **逻辑层**：负责设备鉴权、上下行消息的路由，以及设备会话信息的存储
- **插件层**：负责消息的处理与流转（Kafka / MQTT / API）、消息存储、告警与数据分析等可扩展业务能力

## 核心技术优势

### 安全的设备连接

平台把**设备鉴权单独抽象为一层**，无论设备通过 MQTT 还是 TCP 接入，都要先通过统一的鉴权才能上线。这一点看似基础，却是很多平台缺失的——不少平台对走 TCP 透传的设备根本不做鉴权，设备身份无从校验，极易被伪造或攻击。

- **统一鉴权**：MQTT、TCP 协议设备共用同一套鉴权逻辑，接入标准一致
- **一机一证**：每台设备拥有独立的接入凭证，单台设备凭证泄露不影响其他设备
- **一型一密**：同一产品（型号）共用一套密钥，设备可自动注册激活，便于批量量产接入

### 统一的设备管理

面对种类繁杂的设备，平台通过**产品**和**场景**两层抽象，把杂乱的设备整理成清晰、可管理的结构：

- **产品**：将同一类设备的共性（物模型、协议标识等基础信息）封装为一个"产品"，同类设备归到同一产品下统一定义、统一管理，无需逐台配置
- **场景**：按业务需要把不同类的设备组织到一起（可跨产品、跨类型），还原真实的业务单元，让设备围绕业务而非品类来管理

### 灵活的协议处理

平台开箱内置了行业内通用的主流协议，常见设备无需额外开发即可直接接入：

| 协议 | 说明 |
|------|------|
| **MQTT** | 标准 IoT 设备接入协议，含 **JSON over MQTT** 等常见变种 |
| **TCP** | TCP 透传接入，支持回车换行等分帧方式，适配 DTU 等透传设备 |
| **Modbus** | 工业现场常用协议，支持 Modbus-RTU / TCP，适配传感器、PLC、仪表等工控设备 |
| **自定义协议** | 私有 / 非标协议通过插件化扩展定制，任意设备皆可接入 |

常见设备靠内置协议即插即用，私有、非标协议则通过插件灵活扩展，做到"标准协议开箱即用，私有协议随需定制"。

### 丰富的插件处理

设备接入后的各类处理能力均以**插件**形式提供，开箱即用、按需启用，无需自行搭建：

| 插件能力 | 说明 |
|---------|------|
| **时序数据库** | 内置时序存储，高效写入设备上报数据，历史数据完整可查 |
| **关系数据库** | 存储产品、设备、项目等结构化业务数据 |
| **数据分析** | 支持实时数据分析、历史数据分析与历史曲线展示，对设备数据进行统计、聚合与多维分析 |
| **监控告警** | 支持告警规则的创建与历史告警的查询和处理，按规则实时检测设备数据、触发多级告警 |
| **告警推送** | 告警通过站内、短信、公众号、第三方应用等多渠道推送 |
| **消息流转** | 设备消息可流转至 Kafka / MQTT / API，对接下游业务系统 |

### 开放的对接能力

平台提供多种开放对接方式，方便第三方业务系统与智能体快速接入设备与数据：

- **开放 API**：提供标准化的 OpenAPI，第三方系统通过 AppID / AppSecret 鉴权即可查询设备、读写数据与下发指令
- **实时数据推送**：提供长连接推送能力，设备数据变化实时推送到业务系统，无需轮询
- **智能体接入**：提供面向 AI 智能体的接入能力，可将设备数据与控制能力开放给大模型，实现智能诊断、智能运维等场景

### 项目管理

以“项目 → 场景”两级结构组织设备，适配多业务线、多工地、多园区的管理需求。
